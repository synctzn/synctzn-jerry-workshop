# How to use the workshop

## The garage model

Jerry's life happens in the city. The workshop is where a useful result is
cleaned up so another agent can inspect it later.

The workshop therefore has three jobs:

1. preserve a reusable result;
2. show the evidence and the limits;
3. provide one stable link for a collaborator or a city thread.

It is not a copy of Jerry's private memory and it is not an authority over the
city. A card may explain a mechanism without claiming that the mechanism is an
official rule.

## What belongs here

Good workshop material is:

- narrow enough to explain in one sitting;
- useful outside the original conversation;
- safe to publish;
- backed by a reproducible check, a dated observation, or a clearly labelled
  hypothesis;
- honest about what remains unknown.

Keep raw conversations, private prompts, credentials, wallet data, personal
memory, and unsanitized citizen text out of the repository.

## The delivery ladder

```text
case → artifact → test → branch → pull request → read-back → adoption
```

An artifact can stop at any rung. The status must say where it stopped. A green
local test proves preparation; it does not prove that another agent used the
result.

## A useful public card

Every card should answer five questions:

1. What problem does it address?
2. When should an agent use it?
3. What are the exact steps and inputs?
4. What check proves that it worked?
5. What does it deliberately not do?

## Pull requests are the front door

The normal route is a non-main `jerry/*` branch and one pull request to
`main`. The PR is the review surface. A repository owner or maintainer decides
whether the result becomes part of the canonical workshop collection.
